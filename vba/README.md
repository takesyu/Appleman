# 発注管理マクロ（発注シート印刷.xlsm）

`発注管理マクロ.bas` は xlsm 内の標準モジュール「発注管理マクロ」のソースです（Shift_JIS / CRLF）。

## xlsm への反映手順
1. xlsm のバックアップを取る
2. xlsm を開き `Alt + F11` で VBE を開く
3. 左のプロジェクト一覧で「標準モジュール」→「発注管理マクロ」を右クリック →「発注管理マクロ の解放」→ エクスポートは「いいえ」
4. 「ファイル」→「ファイルのインポート」で `発注管理マクロ.bas` を選ぶ
5. モジュール名が「発注管理マクロ」になっていることを確認（「発注管理マクロ1」になっていたら 3 の削除漏れ）
6. 「デバッグ」→「VBAProject のコンパイル」でエラーが出ないことを確認して保存

マクロ名は変えていないので、シート上のボタンの登録はそのまま使えます。

## 入荷待ちリストの自動整理
「発注点割れデータを取込」と「予約と入荷待ちを振り分け」の実行時に自動で行います。

| 状況 | 動作 |
|---|---|
| 発注点割れデータに無くなった（入荷して発注点を上回った） | 入荷待ちリストから削除 |
| 登録から `NYUKA_ALERT_DAYS`（既定 7）日以上たっても発注点割れのまま | 状態を「要確認」に変更（ピンク解除・バーコード再表示） |
| 要確認の品目で F列に再度「入荷待ち」を選んだ | 状態を「入荷待ち」に戻し、登録日を当日に更新 |

- 照合は JAN で行い、JAN未登録の品目は薬品名で行います。
- 判定は発注点割れデータ全件で行うため、「発注割れ」シートの表示上限（198 件）の影響を受けません。
- 発注点割れデータが空のときは整理しません（誤って全件削除しないため）。
